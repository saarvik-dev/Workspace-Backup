## The better option (for LeetCode DSA)

### ✅ **One question at a time is superior**

**IF** you follow the *right process*.

Why:

- DSA is about **deep pattern recognition**, not task-switching
- Switching between 2–3 problems fragments your thinking
- Optimal solutions require **mental continuity**
Top performers (including ICPC / top LC grinders) **almost always work on one problem at a time**.


---

## The correct way to do “one at a time” (this matters)

### Step-by-step rule (non-negotiable)

1. **Read problem carefully** (2–3 min)
1. **Think brute force first**
- Write time & space complexity mentally
1. **Try to optimize**
- Ask: *What is repeating? Can I use sorting / hash / two pointers / stack / binary search?*
1. **Hard time cap**
- Easy → **10–15 min**
- Medium → **30–40 min**
- Hard → **45–60 min**
👉 If **no clear progress** by then → **STOP**


---

## What to do when stuck (most important)

### ❌ Wrong approach

- Jump to another problem immediately
- Or stare blankly for 2 hours
### ✅ Correct approach

1. **Read editorial / solution**
1. Understand:
- Key observation
- Data structure used
- Why brute force fails
1. **Close the solution**
1. **Re-write the solution yourself**
- Without copy-paste
- Even if it takes time
This is where learning actually happens.


---

## Why NOT 2–3 questions at once?


| Reason | Explanation |
| --- | --- |
| Cognitive load | You lose the core invariant of each problem |
| Illusion of productivity | Feels busy, learns little |
| Pattern dilution | DSA patterns need focus |
| Bad habit | Real interviews give 1 problem |



The only time multiple problems make sense:

- **Very easy problems** (warm-up)
- **After you already know the pattern**
